# AI 项目说明示例

此文件是草案，不会以 `AGENTS.md` 的名称自动生效。负责人补齐实际环境和命令后，可将正文放到仓库根目录的 `AGENTS.md`。

## 目标和结构

- 当前交付主线为旧版二批 CAD 图纸适配，不全面重写项目。
- 开发解决方案：`DWG.Development.sln`，不含安装项目。
- 主程序：`Teigha_Learn_Cad/Teigha_Learn_Cad`。
- `TeighaBase.cs` 承载大量业务逻辑；按任务范围修改，避免全文件重构或格式化。
- 运行依赖和模板在 `vendor`，程序快照在 `app`，均按 manifest 校验。
- 按需阅读 `docs/team/AI协作开发攻略.md` 及本次任务卡。

## 构建和运行

- 传统 .NET Framework v4.0 工程；不要假定 `dotnet build` 即可使用。
- 构建：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Build.ps1`。自检：`Start.ps1 -Build -Check`。所需目标框架环境见 DEPENDENCIES.md。
- 解决方案包含安装项目，应用构建与安装包构建分开说明。
- 新增 C# 文件要核实加入传统 `.csproj` 的 `Compile` 项。
- 遇到缺失工具或依赖，说明限制，不虚构执行成功。

## 工作约定

- 一个任务解决一个可复现的问题，按任务卡范围执行。
- 电气和线束各两人共同负责；按独立问题分配主开发与复核者，每项覆盖输入到输出的完整链路。
- 第一周每组共同完成一个小修复，后续交换角色，具备独立定位能力后再并行。同一函数指定唯一修改者或执行顺序，同根因问题合并处理。
- CAD 原图只读，输出到独立目录；不按文件名和固定坐标硬编码业务结果。
- 保留现有字段含义与模板，公共接口或依赖变化单独协调。
- 业务歧义保留问题与来源，不猜测器件内部导通或连接归属。
- 不覆盖他人修改；不以删除、强制重置或整文件替换处理协作冲突。
- 修改业务逻辑后按验证清单检查，区分实际运行、人工核对与未验证项。
- 交付说明包含原因、修改、证据及限制；生成文件成功不等于业务通过。

## 审查重点

- 检查误连接、漏项、误匹配、共享状态污染、吞异常、样本特判及代码未接入。
- 报告具体触发条件和代码位置，区分事实与假设。
- 开发者通过任务分支提交 PR，最终合并由负责人执行。
