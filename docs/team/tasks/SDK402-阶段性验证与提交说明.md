## 对应问题与已验证结果

2026-10-08 的《测试结果_问题分类汇总.xlsx》是升级前的分类，列出 7、24 号“启动即卡死”，以及 8、19、20、28、29、32、33、35、36、37、48、51 共 12 张“打开失败-图纸版本过高”。后者是当时的用户测试分类，不代表每一张都已独立证明相同底层根因。

| 范围 | 旧版 3.03 | 候选 4.02.2 自动检查 | 结论边界 |
| --- | --- | --- | --- |
| 7、24 | 读取后 Paint 限时未返回 | 实际应用加载、Paint、完整模型遍历并正常退出 | 绘制卡点已解除；实际界面、图面完整性与业务输出仍待人工核对 |
| 8、20、28、29、32、35、36、37、48、51 | 原自动对照记录为读取失败 | 均完成加载、Paint、遍历并正常退出 | 10 张恢复自动打开；不等于分析和导出已正确 |
| 19、33 | 读取失败 | 仍报 `eInvalidFileVersion`，文件版本 `AC1032` | 未解决；见 [SDK402-002](SDK402-002-部分DWG打开失败.md) |

自动对照还验证了 `21 → 7 → 24 → 21` 的加载、Paint 和预期图元数；53 张输入测试前后哈希一致。证据源保留在本机被 Git 忽略的 `artifacts/diagnostics/sdk402-candidate/integration/`：`run.md`、`53输入自动对照.md`、`matrix-results.json` 及逐图日志。向复核者交付时需通过团队批准的位置共享必要日志和样本，原始 DWG 不随本次提交上传；候选 SDK 运行文件位于 `vendor/sdk402/runtime`。

## 代码与运行方式

- 两个 `.csproj` 增加可配置的 CAD SDK 程序集名和目录；未设置时仍使用仓库原有的 3.03 与 .NET Framework 4.0。
- `测试新版SDK.cmd` 调用 `scripts/Start-CadSdkCandidate.ps1`，独立构建 4.02.2/.NET Framework 4.5 并部署到 `artifacts/sdk-candidate/`。候选 SDK 的 76 个运行文件放在 `vendor/sdk402/runtime`，附逐文件哈希清单；已从该仓库路径完成候选构建及启动自检。本机仍需 VC++ 2012 x64 运行库。
- 新 SDK 暴露的保险丝附近圆对象生命周期异常已通过事务内复制圆心/半径修补；24 号锁定图层的读取使用只读打开；7 号总线分析的重复字典键检查改为检查实际插入的终点。修补后的构建和针对性程序探针已有记录，但实际鼠标流程与业务结果尚未完整验收。
- 正常的 `启动软件.cmd`、`编译并启动.cmd` 继续使用旧版。这是候选接入，不应描述为正式默认 SDK 已切换。
