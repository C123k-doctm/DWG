# 验证与提交清单

目前未建立本攻略所述的统一批量回归入口。以下是团队应执行的检查标准，不表示已经有对应脚本或已通过验证。

## 1. 每次保存哪些证据

建议输出放在独立目录，按任务、源码提交和样本组织：

```text
<团队输出根目录>/H-001/<提交SHA>/<样本编号>/
  run.md
  before.xlsx
  after.xlsx
  diff.md
  logs/
  screenshots/
```

修改前结果可单独保存在对应基线提交目录，不必重复复制。`run.md` 至少包含：源码提交、图纸路径及哈希、构建配置、实际 exe、操作步骤、起点/图层/配置、时间、验证人。敏感样本的证据在约定团队存储中共享，在仓库只记录可访问位置。

## 2. 分层验收

| 层次 | 通过条件 | 不能替代的检查 |
| --- | --- | --- |
| 构建 | 相关项目成功编译，新文件加入工程 | 编译通过不证明运行正确 |
| 加载 | 目标 DWG/DXF 正常读取，无未说明的加载错误 | 打开成功不证明全图提取完整 |
| 提取 | 关键图元、文字、表格按人工基准提取 | 候选数量增加不证明准确 |
| 关系 | 接点、器件、端子及路径关系核对通过 | 名称匹配不证明连接成立 |
| 输出 | 字段和模板正确，缺失与歧义有说明 | Excel 保存成功不证明业务正确 |
| 状态 | 重复运行一致，换图没有混入旧图数据 | 单图单次运行不证明状态隔离 |

## 3. 代表样本检查

每个业务修复选择原失败图、相似样式、不同样式和必要反例；同一图可以兼具作用。

按改动选择检查重点：

- 端点容差：确实应连的端点能连接，相邻但不应连接的端点不被吸附。
- 图层规则：导线进入分析；表格、器件边框不被错误当成导线。
- 文本/表格匹配：多个候选不随意取第一个；合并格、换行、重复编号按业务规则处理。
- 器件关系：识别出名称后，仍核对端口归属及接线证据。
- 路径算法：分叉、环路、交叉、断线、未知器件边界按约定处理。
- 长度：明确图上标注、几何长度或推算值的来源与单位。
- 状态：分析 A → 分析 B → 再分析 A，结果没有串用；涉及多标签页时验证相应场景。
- 导出：列位、字段含义、缺失、重复记录和模板没有非预期变化。

必要时补小型几何或数据测试，但真实图纸验证仍要执行。不要把当前错误输出复制为“正确期望”来制造通过测试。

## 4. 逐字段比较

先确认参考 Excel 对应同一张图、同一操作配置及同一业务范围。

比较时列出：漏项、多余项、错配、值错误和未确定项。按人工约定的业务键匹配，业务键不足以唯一定位时记录歧义。排序和规范化只能处理业务允许的表示差异，不应隐藏重复连接或不同端子。

## 5. 回归范围

- 普通任务：开发者验证目标与代表样本，同组人员复核，负责人合并后执行全图回归。
- 公共读取、拓扑、状态、模板变化：合并前组织全图检查，合并后按实际集成变化检查受影响部分。
- 仅攻略等文档变更：检查文件内容、路径和链接，无须运行 CAD 业务测试。

全图台账应覆盖全部 53 张 CAD 输入，分别记录操作、参考结果、打开/分析/导出/业务核对状态。没有人工基准的项目标记“待核对”，不能算业务通过。

## 6. 提交范围检查

- 查看 `git status`、`git diff --stat` 和实际 diff。
- 新增文件与 `.csproj` 接入一致。
- 未混入整个文件格式化、编码/换行变化、个人绝对路径。
- 未提交图纸原件修改、个人凭据或授权密钥。
- 普通构建产物不提交；`vendor` 中的归档依赖不能作为缓存删除，`app` 快照按发布流程更新。
- 无法运行的检查明确记录“未运行”，不能写“通过”。
